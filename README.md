# PASS NOTE

静止球へのインサイドパスを振り返る、日本語のブラウザアプリ。端末内で姿勢を推定し、動画の根拠場面と最大3件の練習案を表示します。指導者による助言の妥当性検証前の初期版です。

## 起動

Node.js 22.12以上を使用してください。

```powershell
npm ci
npm run dev
```

PCで http://localhost:5173 を開きます。同じLANのスマホは、起動時に表示されるNetwork URLでアクセスできます。動画はサーバーへアップロードせず、ブラウザ内だけで処理します。

```powershell
npm test
npm run build
npm run preview
```

## 使い方

1. 明るい場所で、選手1人の頭・両足・静止したボールを横から固定撮影します。
2. インサイドパス1回を含む10〜30秒、100MB以内の動画を選択します。
3. 蹴り足・撮影方向・目的を選び、撮影条件を確認して解析します。
4. 場面候補や助言のボタンを押すと、根拠時刻に移動して関節を重ねた動画を確認できます。
5. 「動画と分析結果を削除」で動画URL、分析結果と処理中のWorkerを破棄します。元の動画ファイルは削除しません。

### YouTubeリンクから解析する

このPCにはYouTube取得用の依存関係を設定済みです。別のPCではPython 3.10以上とFFmpegを用意し、次を実行してください。

```powershell
python -m venv .venv
./.venv/Scripts/python -m pip install -r requirements-youtube.txt
ffmpeg -version
npm run dev
```

FFmpegがない場合は `winget install Gyan.FFmpeg` でインストールし、ターミナルを開き直してください。macOS/Linuxでは `.venv/bin/python` を使用します。

1. 「YouTubeリンク」を選択し、動画URLを貼り付けます。通常動画・youtu.be・Shortsのリンクに対応。
2. パス1回を含む開始位置（秒）と長さ（10・20・30秒）を指定します。URLに付いている時刻指定とは別に、開始位置欄を指定してください。
3. 「解析する」を一度押すと、取得から解析・結果表示まで進みます。蹴り足を変更でき、撮影方向・練習目的は折りたたみ欄から設定します。

公開・録画済み・取得可能な動画のみ対応。ログイン情報やCookieは読み取りません。非公開・年齢制限・地域制限・ライブやYouTube側の取得制限では失敗し、その理由とファイル選択の案内を表示します。利用できる動画を指定してください。

YouTube取得はこのPCのViteサーバーが実行し、720p以下の映像を指定区間だけH.264に変換します。音声は取り込みません。取得は最大120秒・同時1件、動画は100MBまで。姿勢解析の60秒上限とは別です。一時ファイルはブラウザへの転送後、失敗時、中止時に削除します。アプリの強制終了やPCの電源断ではOSの一時フォルダにファイルが残ることがあります。

元動画の開始位置を結果に表示します。根拠ボタンの時刻は切り出した動画の先頭からの時刻です。既存の撮影条件・解析の制約はYouTube動画にも適用されます。

`npm run preview`でも取得APIが動きます。`dist`だけを静的ホスティングした場合はYouTube取得APIがないため対応しません。このAPIは個人・同じLANでの利用を想定し、公開サーバー向けの利用者認証は未実装です。

MP4（H.264）を推奨。MOV・WebMはブラウザがデコードできるもののみ対応。HEVCなどは端末によって再生できません。対象ブラウザは最近のChrome・Edge・Safariを想定していますが、スマホ実機は未検証です。

## 分析と制限

- MediaPipe Pose Landmarker Liteで毎秒6フレームを解析します。最大60秒で中止し、自動再試行しません。
- 暗さ、輪郭の鮮明さ、全身・足の可視性、複数人検出を確認。不適切な条件ではフォーム助言を生成しません。
- 場面は蹴り足の相対移動が最大の時刻の周辺から得た候補。接地とインパクトの実測ではありません。
- 画面上の体幹の傾き、骨盤・軸足・蹴り足の移動から定型文を生成します。LLMを使わず、未計測の値を補いません。
- EfficientDet-Lite0のスポーツ用ボール検出モデルで、全体画像と関節から切り出した足元を解析します。検出枠は黄色、関節は緑で表示。「ボールの検出場面」で根拠時刻へ移動できます。検出スコア30%以上を候補として表示し、未検出時刻に枠を補間しません。複数候補はそのまま表示します。小さいボール・ブレ・遮蔽による見落とし、他のスポーツ用ボールの検出、誤検出はあり得ます。
- 接触位置、足首の向き、実際の重心・荷重、ボール速度・パス精度は判定しません。ボールの位置検出だけでインパクトを確定したり、荷重を推定したりしません。体格・撮影の遠近・遮蔽で2D計測は変わります。
- 撮影状態の閾値と練習案は暫定。指導者の評価を代替しません。F11の過去比較は次段階です。

## プライバシー・費用

選択した動画ファイルと分析結果はページ内のメモリに保持。再選択・削除・ページを閉じた際に破棄します。端末の元動画は残ります。YouTubeリンクはこのPCの取得APIに送られ、このPCからYouTubeへの通信が発生します。取得した区間は一時ファイルとして保持し、転送後に削除します。学習利用しません。モデルとWASMは同梱されておりアプリ配信元から取得します。フォント取得先はGoogle Fontsです。外部有料API費用は0円、通信・配信費用と端末の計算資源は別途です。

## 構成

- `src/video.js`: 動画フレーム、画質確認、Worker通信、時間上限。
- `src/pose.worker.js`: 姿勢推論。
- `src/ball.js`: ボール検出枠の正規化、足元領域、重複候補の統合、検出状況の集計。
- `src/analysis.js`: 入力検証、計測、可視性による抑制、根拠つき助言。
- `src/main.js`: 日本語画面、動画・結果の表示と破棄。
- `src/youtube.js`: 許可したYouTubeリンクと区間の検証。
- `server/youtube.js`: 取得API、タイムアウト・中止・同時実行制限・一時ファイル削除。
- `server/youtube_clip.py`: yt-dlpによる動画解決、FFmpegによる区間変換。
- `docs/PLAN.md`: 開発判断、暫定対象、指導者検証の合格基準案。

姿勢推論の実装は[Google公式ガイド](https://ai.google.dev/edge/mediapipe/solutions/vision/pose_landmarker/web_js)を参照。`public/models`のモデルはGoogleのMediaPipe公式配布物、WASMは`@mediapipe/tasks-vision` 0.10.32の配布物です。モデル・WASMを更新する際は両方を揃えて検証してください。

ボール検出モデルはGoogle公式配布の[EfficientDet-Lite0](https://storage.googleapis.com/mediapipe-models/object_detector/efficientdet_lite0/float32/1/efficientdet_lite0.tflite)（COCOクラスのsports ball）です。サッカー専用モデルではなく、実際の練習動画での精度は検証前です。

YouTube取得は[yt-dlp公式ドキュメント](https://github.com/yt-dlp/yt-dlp)と[EJS設定ガイド](https://github.com/yt-dlp/yt-dlp/wiki/EJS)に沿い、同梱のEJSと既存のNode.jsを利用します。YouTube側の変更で取得できなくなった場合は、yt-dlpを更新して再検証してください。
